# 部署到服务器（Docker）

本文档描述把 AI-Stock 发布到生产服务器的完整流程。基于实际部署环境整理。

---

## 1. 总览

```
                         服务器 115.29.178.22 (阿里云 ECS, Alibaba Cloud Linux 3)
                         /app/aistock/  (docker-compose.server.yml)
┌──────────────┐  8088  ┌─────────────────┐   /api 反代   ┌──────────────┐
│   浏览器      │ ─────▶ │ aistock-frontend │ ───────────▶ │  aistock-api  │
│ (Basic Auth) │        │  nginx (静态托管) │   内网网络    │  .NET Web API │
└──────────────┘        └─────────────────┘              └──────┬───────┘
                         ┌─────────────────┐                     │
                         │ aistock-worker   │                     │
                         │ .NET 后台任务     │                     │
                         │ + zsxq-cli       │                     │
                         └──────┬──────────┬┘                     │
                                │          │      host.docker.internal
            ┌───────────────────┘          └──────────┬──────────┘
            ▼                                          ▼
   阿里云 RDS MySQL                         宿主机 redis:6379 / tdx-stock-web:8080
 (rm-bp185r8xai7txq0ejfo...)                       (复用同机已有容器)
```

**关键设计**
- **不在 Docker 里跑 MySQL**：直连阿里云 RDS（连接串在挂载的 `web.user.json` / `worker.user.json`）。
- **不在 Docker 里跑 Redis**：复用服务器上已有的 `redis` 容器；容器内经 `host.docker.internal:6379` 访问。
- **数据源 tdx**：Worker 经 `host.docker.internal:8080` 访问同机已有的 `tdx-stock-web`。
- **前端不在服务器构建**：服务器内存仅 1.8G，React 生产构建会 OOM。前端在本机构建好静态文件上传，服务器只用 nginx 托管。
- **密钥不进 git / 不进镜像**：全部经卷挂载注入。

> ⚠️ 这台服务器还跑着其他项目（`caddy` 反代占 80/443、`tdx-stock-web` 占 8080、`redis` 占 6379、`agile_config` 占 5000），**勿覆盖、勿用这些端口**。各项目约定放在 `/app/<名字>/`。

## 2. 前置条件（首次，一般已就绪）

服务器（已具备）：Docker 26+、docker compose v2、git、node（宿主机的 node 仅用于别处，zsxq-cli 实际在容器里跑）。

```bash
# 1) swap：1.8G 内存必须加 swap，否则构建/运行 OOM（会连带杀掉别的容器）
fallocate -l 4G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
grep -q /swapfile /etc/fstab || echo '/swapfile none swap sw 0 0' >> /etc/fstab

# 2) swappiness：默认 0 会宁可 OOM 也不用 swap，调高
sysctl -w vm.swappiness=60
grep -q 'vm.swappiness' /etc/sysctl.conf || echo 'vm.swappiness=60' >> /etc/sysctl.conf   # 持久化
```

本机（Windows，用于上传代码 / 构建前端）：已配 SSH 免密到 `root@115.29.178.22`、装有 Node。

> 注：服务器**访问不了 GitHub**（443 超时），所以代码用 scp 上传，不在服务器 `git clone`。

## 4. 配置文件准备（密钥，不进 git）

这三类文件需手动放到服务器，**不在仓库里**：

### 4.1 `config/web.user.json` 和 `config/worker.user.json`
基于本机 `AIStock.Web/appsettings.user.json` / `AIStock.Worker/appsettings.user.json`，**改两处**后放到服务器：
- `ConnectionStrings.Redis` → `host.docker.internal:6379,password=...`（容器经宿主网关访问 redis）
- Worker 的 `DataSync.StockCodesUrl` → `http://host.docker.internal:8080/api/codes`
- MySQL 连接串（阿里云 RDS）保持不变。

### 4.2 `.env`（Basic Auth 密码）
```bash
cat > /app/aistock/.env <<'EOF'
BASIC_AUTH_USER=admin
BASIC_AUTH_PASSWORD=改成你的密码
EOF
chmod 600 /app/aistock/.env
```

### 4.3 `config/zsxq-cli/`（知识星球登录态）
首次为空目录即可，登录后自动生成（见第 7 节）。

## 5. 首次完整部署

### 5.1 上传代码（本机执行）
```powershell
# 打包源码（排除 node_modules/bin/obj/.git/.vs/build）
tar -czf $env:TEMP\aistock-src.tar.gz -C "D:\代码\repos\AI-Stock" `
  --exclude=.git --exclude=.vs --exclude=node_modules --exclude=bin `
  --exclude=obj --exclude=web/build --exclude=logs .

# 上传 + 解压
scp $env:TEMP\aistock-src.tar.gz root@115.29.178.22:/tmp/
ssh root@115.29.178.22 "mkdir -p /app/aistock && tar -xzf /tmp/aistock-src.tar.gz -C /app/aistock"
```

### 5.2 上传密钥配置（本机执行）
```powershell
ssh root@115.29.178.22 "mkdir -p /app/aistock/config"
scp web.user.json    root@115.29.178.22:/app/aistock/config/web.user.json
scp worker.user.json root@115.29.178.22:/app/aistock/config/worker.user.json
# .env 见 4.2，在服务器上创建
```

### 5.3 构建前端静态文件（本机执行）
```powershell
cd "D:\代码\repos\AI-Stock\web"
$env:REACT_APP_API_BASE_URL="/api"; $env:GENERATE_SOURCEMAP="false"; $env:CI="false"
npm install        # 首次
npm run build
# 上传 build/
tar -czf $env:TEMP\fe.tar.gz -C "D:\代码\repos\AI-Stock\web" build
scp $env:TEMP\fe.tar.gz root@115.29.178.22:/tmp/
ssh root@115.29.178.22 "rm -rf /app/aistock/web/build && tar -xzf /tmp/fe.tar.gz -C /app/aistock/web"
```

### 5.4 准备基础镜像（服务器执行，Docker Hub 在国内慢，用 DaoCloud 拉再 tag）
```bash
for img in node:20-bookworm-slim nginx:1.27-alpine; do
  docker pull docker.m.daocloud.io/library/$img && docker tag docker.m.daocloud.io/library/$img $img
done
# .NET 的 mcr.microsoft.com 镜像可直连，无需处理
```

### 5.5 构建并启动（服务器执行）
```bash
cd /app/aistock
docker compose -f docker-compose.server.yml build      # api / worker / frontend 逐个构建
docker compose -f docker-compose.server.yml up -d
docker compose -f docker-compose.server.yml ps
```

### 5.6 验收
```bash
# 健康检查（免密）
curl http://localhost:8088/api/health          # 期望 {"status":"Healthy","redis":{"connected":true}...}
# 带密码访问首页
curl -u admin:密码 -o /dev/null -w '%{http_code}\n' http://localhost:8088/   # 期望 200
docker logs aistock-api --tail 20
docker logs aistock-worker --tail 20
```
外网访问：**http://115.29.178.22:8088**（需阿里云安全组放行 8088）。

## 7. 知识星球 zsxq-cli 登录

zsxq-cli 已内置在 Worker 镜像里（仅能在容器跑——其二进制需 glibc≥2.34，宿主机 glibc 太老跑不了）。登录态存 `/app/aistock/config/zsxq-cli/`，挂载持久化，重启不丢。

**首次登录 / token 失效后重新登录：**
```bash
# 1) 取授权链接（不轮询）
docker exec aistock-worker zsxq-cli auth login --no-browser --no-wait --json
#    输出里有 verification_uri_complete 和 device_code
# 2) 用手机/浏览器打开该链接完成授权
# 3) 用上一步的 device_code 完成登录
docker exec aistock-worker zsxq-cli auth login --device-code <device_code>
# 4) 确认
docker exec aistock-worker zsxq-cli auth status
```

**手动触发一次采集验证：**
```bash
curl -u admin:密码 -X POST http://localhost:8088/api/workerconfig/jobs/knowledge-star/run
docker logs aistock-worker --since 30s | grep 知识星球
```

## 8. 常用运维

| 操作 | 命令（服务器，`cd /app/aistock`） |
|---|---|
| 看状态 | `docker compose -f docker-compose.server.yml ps` |
| 看日志 | `docker logs aistock-api -f` / `aistock-worker` / `aistock-frontend` |
| 重启某服务 | `docker compose -f docker-compose.server.yml restart aistock-api` |
| 全部重启 | `docker compose -f docker-compose.server.yml up -d` |
| 停止 | `docker compose -f docker-compose.server.yml down`（不删 RDS/redis，它们在外部） |
| 改 Basic Auth 密码 | 改 `.env` → `docker compose -f docker-compose.server.yml up -d aistock-frontend` |
| 改 Worker 任务调度 | 前端「任务配置」页（worker_config 表为权威，热生效），或 `PUT /api/workerconfig/jobs` |

## 10. 踩坑记录（部署时遇到并已解决）

| 问题 | 原因 / 解决 |
|---|---|
| `dotnet restore` 报 NU1107 版本冲突 | 用了中央包管理，Dockerfile 需在 restore 前 `COPY Directory.Packages.props`（已修） |
| Debian `apt-get update` 极慢（10+ 分钟） | `deb.debian.org` 在 ECS 上慢，Dockerfile 已换 `mirrors.aliyun.com` |
| Web 镜像构建卡在装 Playwright | Web 不做抓取（`Playwright:CheckOnStartup` 默认关），已从 Web Dockerfile 移除 Chromium |
| 前端 react 构建被 OOM 杀（连带杀别的容器） | 1.8G 内存不够 + `swappiness=0`。改为**本机构建静态文件上传**；并加 swap、调 swappiness |
| Docker Hub 拉 node/nginx 极慢 | 用 `docker.m.daocloud.io/library/<img>` 拉取再 `docker tag` |
| zsxq-cli 在宿主机报 `GLIBC_2.34 not found` | 宿主 Anolis glibc 2.32 太老；只能在 Debian bookworm 容器（glibc 2.36）里跑 |
| 容器内 zsxq-cli 登录 TLS 失败 | 精简镜像缺 `ca-certificates`；Worker 的 .NET 基础镜像自带，无此问题 |
| RDS 连不上 | 服务器公网 IP 需加入阿里云 RDS 白名单 |
| eastmoney 数据源反复超时 ERR | 走代理隧道偶发，不影响（有 sanhu/tencent/tdx 兜底） |
