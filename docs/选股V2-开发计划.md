## Phase 2：策略拆分（已完成）

### 目标
从"单一打分模型"升级为"策略池"：不同市场风格用不同策略，同一活跃池上各自选股。

### 成果
- **共享打分器 `SelectionScorers`**：抽取 8 因子打分为纯静态函数（含趋势口径 `TechnicalTrend`/`PositionTrend`），各策略复用、口径不漂移。重构后现有引擎测试全绿（行为锁）。
- **策略接口 `ISelectionStrategy` + 基类 `WeightedSelectionStrategyBase`**：统一"硬过滤→8 因子→权重加权→涨停惩罚→大盘系数→TOP-N"骨架。
- **三策略**：
  - `LowDipStrategy`（lowdip，默认）：委托现有引擎，行为与历史完全一致（低吸埋伏，左侧）
  - `TrendStrategy`（trend）：右侧追强，容忍高 RSI、要求站上 20 日线、位置甜区为趋势中段、不惩罚涨停
  - `ThemeStrategy`（theme）：硬门槛=必须命中当日热门题材，侧重题材/板块/龙头
- **配置中心按策略隔离**：配置 `Name` = 策略 key，每策略独立版本管理。
- **Service/API**：`StockSelectionService` 注入策略池、按 `strategyKey` 路由；`GET /api/selection/strategies` 列策略；`screen`/`run` 支持 `?strategy=`。
- **前端**：选股页 + 配置页加策略下拉（按策略存取配置 / 按策略选股）。
- **测试**：新增 5 个策略测试（Trend 容忍高 RSI、要求均线、Theme 题材门槛等），全套 **101 测试通过**。

### 待用户验收
- 同 Phase 1（连库启动后）：`GET /api/selection/strategies` 看三策略；`POST /api/selection/run?strategy=trend` 看趋势选股；前端选股页/配置页切换策略。

### 未做（留后续）
- Reversal（超跌反弹）策略：按原计划后置，待 Phase 3 回测框架验证各策略有效性后再加。
- 各策略默认权重目前相同（差异在过滤口径与因子口径）；细分权重待 Phase 6 因子研究后按 IC 结果调。

## Phase 3：统一回测框架（已完成 — 历史回测）

### 目标
为策略/选股结果提供严谨、可单测的回测，作为后续因子研究与动态权重的地基。

### 成果
- **`BacktestEngine`（纯计算，严格单测）**：信号 + 日 K → 模拟成交。
  - 买点：T+1 开盘（默认，贴近实盘）/ 信号日收盘；持有 N 个交易日收盘卖出，不足则持有到最后一根。
  - 统计：胜率、平均/中位收益、盈亏比、收益标准差、按时间累计收益曲线的最大回撤、平均最高浮盈/最大浮亏、最佳/最差、数据缺失跳过计数。
  - 容错：信号日停牌（取≥信号日的首根）、无次日数据、买入价非正等均安全跳过。
- **`BacktestService`**：把 `selection_result` 历史当信号（同日同股去重）+ `kline_data` → 回测报告。
- **API**：`GET /api/selection/backtest?holdDays=&entry=&from=&to=`。
- **前端**：选股回测页（持有期/买点/区间 → 统计卡片 + 成交明细表）。
- **测试**：回测引擎 5 个 + 回测服务 3 个，全套 **109 测试通过**。

### 设计取舍 / 未做
- 本阶段回测的是**已落库的历史选股结果**（真实选过的，主要为默认 lowdip）。
- **策略回放回测**（在历史快照上对每个交易日重跑 trend/theme 策略生成信号再回测）**未做**：依赖
  daily_market_snapshot 的历史深度 + 大盘环境/题材的逐日回放，复杂度与误差较高，留待快照历史
  积累后单独做（结合 Phase 4）。这样能跨策略横向对比表现。
- 未计交易成本/滑点/涨跌停不可成交；等权独立成交，不建组合资金曲线（最大回撤为收益序列近似）。

### 待用户验收
- 连库启动后：先有若干历史选股记录（`POST /api/selection/run` 多日，或导入），再
  `GET /api/selection/backtest?holdDays=5` 看报告；前端「选股回测」页运行。

## Phase 4：市场状态识别增强（已完成）

### 目标
从 3 档松紧（弱/中/强）升级为 4 种市场状态识别，并据此推荐策略，驱动"市场决定策略"。

### 成果
- **`RegimeKind`（4 态）**：Range 震荡 / TrendUp 趋势上涨 / ThemeMarket 题材主导 / RiskOff 风险释放。
- **`MarketRegimeClassifier`（纯函数，可单测）**：综合指数均涨跌、站上 20 线比例、涨跌广度、涨停/跌停家数判定状态并给推荐策略：
  - RiskOff（指数大跌/涨家极少/跌停潮）→ 低吸防守
  - TrendUp（指数走强+普涨+多数站上 20 线）→ 趋势跟随
  - ThemeMarket（涨停潮、结构性活跃）→ 题材龙头
  - Range（其余）→ 低吸埋伏
- `ComputeMarketRegimeAsync` 接入：填充 Kind/RecommendedStrategy/涨停跌停数，描述追加"市场状态：X"。
- **推荐透传到选股结果** `RecommendedStrategy`，前端选股页提示"当前市场建议用 X 策略"并可一键切换。
- **测试**：分类器 5 个，全套 **114 测试通过**。

### 阈值说明
分类阈值为经验值（如涨停潮 ≥1.2% 且 ≥30 家、趋势 avgIndexChange≥0.8% 且涨家≥60%），已标注，后续可按回测校准。

## Phase 5：动态策略权重（半自动达成）

### 已达成（人工半自动）
Phase 4 的"市场状态 → 推荐策略 + 前端一键切换"即原计划"先人工半自动"的核心：系统识别市场状态、
给出策略建议，用户确认后切换。规避了纯自动的过拟合风险（原评估即建议保留人工干预）。

### 未做（全自动动态权重）
按最近 N 日各策略表现自动分配权重，需 **Phase 3 的"策略回放回测"** 作为地基（在历史快照上逐日重跑
各策略得到可对比的策略级收益序列）。该回放回测本阶段未做（见 Phase 3 取舍），故全自动动态权重暂缓，
避免无地基硬做。

## 附加：策略优化 MCP 接口（已完成）

> 需求：提供接口给大模型，让其自主优化策略并看回测效果。决策：**MCP Server（.NET 自包含）+ LLM 全自动迭代 + 目标(盈亏比+胜率+控回撤) + LLM 可直接激活**。

### 地基补齐：参数回放回测（Phase 3 曾 deferred）
- `SelectionContextBuilder`（纯函数）：按任意历史交易日构造题材/板块/无指数简化大盘环境。
- `ReplayBacktestService.BacktestParamsAsync`：用**给定参数**在历史区间逐日重跑选股 → 汇总信号 → `BacktestEngine` 回测。这是"换参数看效果"的核心能力（之前只能回测已落库结果）。
- API：`POST /api/selection/backtest/replay`（body=criteria，query=strategy/from/to/holdDays）。
- 测试：回放 3 个（产信号、参数收紧→无信号验证参数生效、空数据），全套 **117 通过**。

### MCP Server（`AIStock.Mcp`）
- .NET 控制台 + `ModelContextProtocol` 1.3.0，stdio，自包含（直连 DB，不需 Web 运行）。
- 7 工具：`list_strategies` / `get_default_config` / `get_active_config` / `replay_backtest` / `backtest_history` / `save_config` / `list_configs`。
- 验证：`initialize → tools/list` 握手通过，7 工具正确注册（占位连接串，不碰生产库）。
- 接入文档：`docs/MCP接入说明.md`（Claude Desktop 配置 + 优化工作流提示词）。

### 安全/边界
- 连接串经 `env` 注入（不入库文件）。`save_config(activate=true)` 按用户要求**开放给模型直接激活**生效参数；回退用 `list_configs` + 重新激活旧版本。
- 回测不计成本/滑点；回放深度受快照历史限制。

## 回放回测接入历史指数（已完成）

> 起因：回放回测原用"无指数简化大盘环境"。要参考指数有两个障碍——① 不能用实时指数接口回测历史（**前视偏差**）；② 指数历史此前未入库。

### 成果
- **统一 `RegimeEvaluator`（纯函数）**：实盘选股与回放共用同一套 Level/Kind/推荐策略判定（消除两处重复 score 逻辑，口径一致）。含指数清单 `MarketIndices` 与 `QuoteFromCloses`。
- **指数历史落库**：复用 `kline_data`（指数以东财 secid 作 code，与6位个股不冲突）。Worker 新增 `IndexKlineSyncService` + `index-kline` 任务（`RunOnStartup=true` 启动即回补 ~300 日，之后每日17点更新）。
- **回放按日构造历史指数**：`ReplayBacktestService` 预载指数历史K，对每个交易日取"截至当日"的指数（无前视）→ `SelectionContextBuilder.BuildRegime(dayShots, indices)` → `RegimeEvaluator`。指数缺失时优雅降级为仅广度。
- **实盘重构验证**：`ComputeMarketRegimeAsync` 改用 `RegimeEvaluator`，行为不变（现有测试全绿）。
- **测试**：RegimeEvaluator 5 个（强/弱/无指数保守/QuoteFromCloses），全套 **122 通过**。

### 待用户验收
1. Worker 跑 `index-kline`（启动即回补，或等收盘后）：库内 `kline_data` 出现 code 为 `1.000001` 等指数行。
2. 之后调 `replay_backtest`（或 MCP 同名工具），回放即用真实历史指数判定大盘，回测更贴近实盘。

## 回放脱离 daily_market_snapshot（已完成）

> 起因：回放原依赖 daily_market_snapshot，历史深度受采集起点限制。决策：**回放改为从 kline_data 实时重建技术面 + 轻量资金流表补资金面**，不再依赖 snapshot，历史深度扩展到 K 线覆盖范围。

### 关键认识
- snapshot 本质是"K线衍生技术指标 + 资金流"的冗余存储；技术面(MA/RSI/MACD via IFeatureCalculator、量比/均价/振幅/位置/涨停 via K线)完全可从 kline_data 重建（与实盘同口径，量比/均价为 K 线近似）。
- 唯一 kline 没有的是**主力净流入**；东财 `fflow/daykline?lmt=0` 本就返回全历史（现有代码只取了最新一天）。
- 全市场逐日回放需全市场每日资金流，逐股实时调接口不现实 → 落一张**轻量资金流表** `daily_capital_flow`。

### 步骤
- [x] ① 数据层：`CapitalFlowEntity`(daily_capital_flow) + Migration；`EastmoneyProvider.GetCapitalFlowHistoryAsync`(解析全历史)；`CapitalFlowSyncService` + Worker `capital-flow` 任务(批量限流)
- [x] ② 回放层：`SnapshotRebuilder`(kline+资金流 → 内存 DailyMarketSnapshotEntity，技术面复用 IFeatureCalculator、同口径)；`ReplayBacktestService.RebuildAllSnapshotsAsync` 重建全市场当日快照，**不再读 daily_market_snapshot**；MCP 项目补 Feature 依赖
- [x] ③ 测试：SnapshotRebuilder 2 + 回放重写 3，全套 **124 通过**
