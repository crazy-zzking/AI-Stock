# AIStock.Selection V2.0 开发计划

> 总目标：从「经验参数单策略」升级为「市场状态驱动 + 多策略 + 配置中心 + 版本管理 + 统一回测 + 动态组合」的可验证量化平台。
> 按优先级分阶段落地，每阶段先列计划→确认→开发→测试验收→更新本文档进度。

## 优先级路线图

| 优先级 | 阶段 | 内容 | 状态 |
|---|---|---|---|
| **最高** | **Phase 1** | **配置中心 + 版本管理** | ✅ 完成（UI 视觉细节待用户验收） |
| 高 | Phase 2 | 策略拆分（LowDip / Trend / Theme，Reversal 后置） | ✅ 完成 |
| 高 | Phase 3 | 统一回测框架（严谨版） | ✅ 完成（历史回测；策略回放后续） |
| 中 | Phase 4 | 市场状态识别增强（Range/TrendUp/ThemeMarket/RiskOff） | ✅ 完成 |
| 低 | Phase 5 | 动态策略权重（先人工半自动） | ◗ 半自动达成（全自动待回放回测） |
| 暂缓 | Phase 6 | IC / RankIC / 消融实验（依赖数据覆盖度） | ⬜ 暂缓（前置未满足） |

## Phase 1：配置中心 + 版本管理（当前）

### 目标
把选股的全部可调参数（阈值 + 8 个因子权重 + 大盘环境系数）从代码硬写改为**数据库存储、版本化管理、运行时内存加载**，并提供前端配置管理界面。

### 设计决策（已确认）
- **存储格式**：整体 JSON 版本化（一条记录存一份完整配置 JSON）
- **配置范围**：`SelectionCriteria` 全部阈值 + 引擎 8 因子权重 + Regime 三系数（weak/strong/neutral）
- **交付**：后端 + 前端一起做
- **建表方式**：EF Core Migration（项目现用 `MigrateAsync`）

### 配置范围边界（重要）
- ✅ 本阶段提取：8 因子顶层权重、Regime 系数、`SelectionCriteria` 所有阈值
- ❌ 暂不提取：各因子内部的分档明细值（如 `ScoreCapital` 里的 100/85/70/55、`LimitUpPenalty` 罚分档）——留待 Phase 6 因子研究阶段，避免本阶段参数爆炸

## Phase 2：策略拆分（已完成）

### 目标
从"单一打分模型"升级为"策略池"：不同市场风格用不同策略，同一活跃池上各自选股。

### 成果
- **共享打分器 `SelectionScorers`**：抽取 8 因子打分为纯静态函数（含趋势口径 `TechnicalTrend`/`PositionTrend`），各策略复用、口径不漂移。重构后现有引擎测试全绿（行为锁）。
- **策略接口 `ISelectionStrategy` + 基类 `WeightedSelectionStrategyBase`**：统一"硬过滤→8 因子→权重加权→涨停惩罚→大盘系数→TOP-N"骨架。
- **三策略**：
  - `LowDipStrategy`（lowdip，默认）：委托现有引擎，行为与历史完全一致（低吸埋伏，左侧）
  - `TrendStrategy`（trend）：右侧追强，容忍高 RSI、要求站上 20 日线、位置甜区为趋势中段、不惩罚涨停
  - `ThemeStrategy`（theme）：硬门槛=必须命中当日热门题材，侧重题材/板块/龙头
- **配置中心按策略隔离**：配置 `Name` = 策略 key，每策略独立版本管理。
- **Service/API**：`StockSelectionService` 注入策略池、按 `strategyKey` 路由；`GET /api/selection/strategies` 列策略；`screen`/`run` 支持 `?strategy=`。
- **前端**：选股页 + 配置页加策略下拉（按策略存取配置 / 按策略选股）。
- **测试**：新增 5 个策略测试（Trend 容忍高 RSI、要求均线、Theme 题材门槛等），全套 **101 测试通过**。

### 待用户验收
- 同 Phase 1（连库启动后）：`GET /api/selection/strategies` 看三策略；`POST /api/selection/run?strategy=trend` 看趋势选股；前端选股页/配置页切换策略。

### 未做（留后续）
- Reversal（超跌反弹）策略：按原计划后置，待 Phase 3 回测框架验证各策略有效性后再加。
- 各策略默认权重目前相同（差异在过滤口径与因子口径）；细分权重待 Phase 6 因子研究后按 IC 结果调。

## Phase 3：统一回测框架（已完成 — 历史回测）

### 目标
为策略/选股结果提供严谨、可单测的回测，作为后续因子研究与动态权重的地基。

### 成果
- **`BacktestEngine`（纯计算，严格单测）**：信号 + 日 K → 模拟成交。
  - 买点：T+1 开盘（默认，贴近实盘）/ 信号日收盘；持有 N 个交易日收盘卖出，不足则持有到最后一根。
  - 统计：胜率、平均/中位收益、盈亏比、收益标准差、按时间累计收益曲线的最大回撤、平均最高浮盈/最大浮亏、最佳/最差、数据缺失跳过计数。
  - 容错：信号日停牌（取≥信号日的首根）、无次日数据、买入价非正等均安全跳过。
- **`BacktestService`**：把 `selection_result` 历史当信号（同日同股去重）+ `kline_data` → 回测报告。
- **API**：`GET /api/selection/backtest?holdDays=&entry=&from=&to=`。
- **前端**：选股回测页（持有期/买点/区间 → 统计卡片 + 成交明细表）。
- **测试**：回测引擎 5 个 + 回测服务 3 个，全套 **109 测试通过**。

### 设计取舍 / 未做
- 本阶段回测的是**已落库的历史选股结果**（真实选过的，主要为默认 lowdip）。
- **策略回放回测**（在历史快照上对每个交易日重跑 trend/theme 策略生成信号再回测）**未做**：依赖
  daily_market_snapshot 的历史深度 + 大盘环境/题材的逐日回放，复杂度与误差较高，留待快照历史
  积累后单独做（结合 Phase 4）。这样能跨策略横向对比表现。
- 未计交易成本/滑点/涨跌停不可成交；等权独立成交，不建组合资金曲线（最大回撤为收益序列近似）。

### 待用户验收
- 连库启动后：先有若干历史选股记录（`POST /api/selection/run` 多日，或导入），再
  `GET /api/selection/backtest?holdDays=5` 看报告；前端「选股回测」页运行。

## Phase 4：市场状态识别增强（已完成）

### 目标
从 3 档松紧（弱/中/强）升级为 4 种市场状态识别，并据此推荐策略，驱动"市场决定策略"。

### 成果
- **`RegimeKind`（4 态）**：Range 震荡 / TrendUp 趋势上涨 / ThemeMarket 题材主导 / RiskOff 风险释放。
- **`MarketRegimeClassifier`（纯函数，可单测）**：综合指数均涨跌、站上 20 线比例、涨跌广度、涨停/跌停家数判定状态并给推荐策略：
  - RiskOff（指数大跌/涨家极少/跌停潮）→ 低吸防守
  - TrendUp（指数走强+普涨+多数站上 20 线）→ 趋势跟随
  - ThemeMarket（涨停潮、结构性活跃）→ 题材龙头
  - Range（其余）→ 低吸埋伏
- `ComputeMarketRegimeAsync` 接入：填充 Kind/RecommendedStrategy/涨停跌停数，描述追加"市场状态：X"。
- **推荐透传到选股结果** `RecommendedStrategy`，前端选股页提示"当前市场建议用 X 策略"并可一键切换。
- **测试**：分类器 5 个，全套 **114 测试通过**。

### 阈值说明
分类阈值为经验值（如涨停潮 ≥1.2% 且 ≥30 家、趋势 avgIndexChange≥0.8% 且涨家≥60%），已标注，后续可按回测校准。

## Phase 5：动态策略权重（半自动达成）

### 已达成（人工半自动）
Phase 4 的"市场状态 → 推荐策略 + 前端一键切换"即原计划"先人工半自动"的核心：系统识别市场状态、
给出策略建议，用户确认后切换。规避了纯自动的过拟合风险（原评估即建议保留人工干预）。

### 未做（全自动动态权重）
按最近 N 日各策略表现自动分配权重，需 **Phase 3 的"策略回放回测"** 作为地基（在历史快照上逐日重跑
各策略得到可对比的策略级收益序列）。该回放回测本阶段未做（见 Phase 3 取舍），故全自动动态权重暂缓，
避免无地基硬做。

---

## Phase 6：因子研究（IC/RankIC/消融）— 暂缓

依赖：① 足够的历史快照深度（IC 需全市场 × 长周期的因子值与未来收益对齐）；② Phase 3 策略回放回测。
当前 daily_market_snapshot 历史深度有限，强行计算 IC 结论会失真。前置条件满足后再做。
