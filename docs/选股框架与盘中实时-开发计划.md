## 📌 现状澄清：daily_market_snapshot 已是"盘中实时快照层"（无需改造）
> 之前一度误判它"只是收盘后东财采集、需要改造回盘中实时"——错误，纠正如下。

`MarketSnapshotSyncService` 有两个方法，由 `MarketSnapshotSyncJob` 按 `EnableIntraday`（默认 true）选择：
- **盘中（默认）**：`SyncIntradayAsync` —— 每 `IntradayIntervalMinutes`(默认20) 分钟，**腾讯批量实时报价** + 库内历史日K拼当日 bar + `IFeatureCalculator` 算动态指标 + 东财批量主力净流入 → upsert `daily_market_snapshot` 当日行。**这就是盘中/尾盘实时选股的数据源。**
- **收盘后/未启用盘中**：`SyncAsync` —— 东财逐只采集。

**数据分层全貌**：
| 层 | 数据源 | 用途 |
|---|---|---|
| 盘中实时 | `daily_market_snapshot`（腾讯实时报价+东财主力流入+IFeatureCalculator） | 盘中/尾盘实时选股（实盘 `LoadAsync` 读它）|
| 收盘/历史 | `kline_data`+`daily_capital_flow`（`SnapshotRebuilder`+IFeatureCalculator） | 回测；可选作收盘后选股 |

**残留差异（轻）**：盘中行情源是腾讯、回测重建用东财日K，源不同有细微口径差异；但技术指标用**同一个 `IFeatureCalculator`**，差异远小于早先判断。

## 🔗 选股 ↔ 交易未打通（最大待开发点 / 尾盘自动下单落地路径）
> 全项目过一遍 git + 读交易闭环代码后的结构性结论。

**现状：选股线 与 自主交易线 是两条独立、未连接的线。**

| 线 | 模块 | 信号来源 | 状态 |
|---|---|---|---|
| 选股线 | `Selection` | lowdip/trend/theme 埋伏选股 + 因子 + 回测 | 成熟（本文档主体）|
| 自主交易线 | `Orchestrator`+`Strategy`+`Execution` | **`AlphaAgent` 用 `IEnumerable<IStrategy>`（MA突破/网格/配对技术策略）** | 代码完整但冷置、DryRun |

**关键**：`AlphaAgent.GenerateSignalAsync` 依赖的是 `AIStock.Strategy` 的技术交易策略，**不是 `ISelectionStrategy`**。即**选股选出的票(selection_result)没有流入下单链路**，自主交易自己另跑一套 MA突破/网格，与选股成果(v2.1/尾盘)无关。

**交易闭环本身很成熟**（非占位，生产级）：
- `TradingGate`：kill-switch、每日限单、在途买入原子预留(防并发超配)、股票级熔断、连续失败自动暂停
- `OrderManagerService`：单笔上限/账户校验/敞口预留，DryRun(记意向单)/Live(真调券商 `PlaceBuyOrderAsync`) 双路径
- `AutonomousDecisionSystem`：分析(research-agent)→信号(alpha-agent)→风控(risk-agent)→下单(OrderManager) 4 步，仓位 `PositionSizer`(Kelly)
- 全局默认 `Trading.Mode=DryRun`

**真正待开发 = 选股→交易的衔接**（与尾盘买入主线完全重合）：
```
选股引擎(lowdip v2.1, 尾盘口径) → TOP-N
  → PositionSizer 算仓位 → TradingGate 护栏 → OrderManager 下单(先 DryRun)
```
- 下半截(护栏+下单+仓位)**全部现成可复用**，只需写"选股结果 → OrderRequest"的衔接服务 + 尾盘(14:55)触发调度
- **不要走 `AlphaAgent`/`AIStock.Strategy` 那套**（MA突破/网格与选股无关）；尾盘自动下单应直接从 selection_result 驱动 OrderManager
- 先 DryRun 跑通链路 + 记录意向单，与尾盘回测(SignalClose)结果对照，再考虑 Live

**未核实边界**：`ResearchAgent`/`RiskAgent`/`AlphaEngine` 内部与 `AIStock.Strategy` 三个技术策略的质量未细看；"两条线脱节"从 `AlphaAgent` 依赖类型已可确定。

## 🛠️ MVP 开发计划：选股 → 尾盘自动下单（DryRun）

- ✅ **下单/账户接口真实现**：`SanhuProvider` 声明 `DataCapability.Trading`，`GetAccountInfoAsync`/`PlaceBuyOrderAsync` 真接散户量化交易接口（非桩）

  - **Web** 注册全套：`AddRiskServices/AddSelectionServices/AddExecutionServices/AddOrchestratorServices` + Sanhu 完整配置(Token+**MyKey**)
  - **Worker** 只 `AddDataProviders`（数据采集），**无 Selection/Execution**，Sanhu **缺 MyKey**，无 `Trading` 配置段
- → **计划修正：尾盘下单服务放 Web，不放 Worker**。用 Web 的 `IHostedService`/`BackgroundService` 做 14:55 定时触发（Web 依赖+配置现成，DryRun 立即可跑）；放 Worker 要补注册 Selection+Execution、补 MyKey、补 Trading 段，得不偿失。代价：Web 无现成 JobScheduler，需加一个轻量定时 BackgroundService。

## 重要笔记（踩过的坑）
1. **回测数据在漂移**：Worker 持续采集会改 `kline_data`/`capital_flow`，同参数回测绝对值随时间变；因子对比必须**同一次运行内**做。
2. **盘中 vs 回测口径**：盘中 snapshot 用腾讯实时、回测重建用东财日K，源不同有细微差异（技术指标同 IFeatureCalculator）。
3. **加因子 ≠ 有效**：引擎算法增强（接飞刀/回踩协同/派发惩罚）和 RelativeStrength 均经回测证伪并回滚/不启用。每个新因子必须回测验证。
4. **买入时点**：MCP `replay_backtest` 默认 `NextOpen`（次日开盘）；尾盘策略须显式传 `entry=SignalClose`。早期 v2.0/v2.1 调参用的是 NextOpen，已用 SignalClose 复核 v2.1 仍成立。
5. **MCP 调用**：本会话靠 `scripts/mcp_call.ps1` stdio 驱动 `AIStock.Mcp.exe`（需设 `$env:MCP_MYSQL`、`$env:MCP_EXE`）。**脚本内勿写中文**（PowerShell 5.1 按 GBK 读无 BOM UTF-8 .ps1 会乱码破坏语法）。
6. **重建 MCP 的锁**：Claude Desktop 长驻 Release 版锁 `bin/Release`；改完用 **Debug** 构建并 `$env:MCP_EXE` 指向 Debug exe 测试，Desktop 用新版需重启。
