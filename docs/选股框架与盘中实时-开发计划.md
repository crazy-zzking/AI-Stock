# 选股策略框架 + 因子库 + 盘中实时改造 — 开发计划与进度

> 本文档记录"可配置策略框架 / 因子库扩展 / daily_market_snapshot 盘中实时改造"三块工作的设计、已完成进度与待办，供后续会话接续。

## 总体目标
1. **可配置策略框架**：让用户在前端组合"过滤口径 + 因子口径 + 权重"创建新选股策略，无需改代码部署。
2. **因子库扩展**：在现有 8 因子基础上增加经回测验证有效的新因子。
3. **盘中实时层改造**：让 `daily_market_snapshot` 回归"盘中实时"本职，与"收盘后/回测走 kline+capital_flow 重建"两层各司其职。

### 独立重构：daily_market_snapshot 改造为盘中实时层
**背景**：当前 `MarketSnapshotSyncService` 是收盘后用东财 API 采集，与 kline+capital_flow 重建职责重叠、引入实盘/回测口径漂移。目标让两层各司其职。

| 层 | 表 | 特性 | 用途 |
|---|---|---|---|
| 盘中实时 | `daily_market_snapshot` | 动态（实时价近似当日收盘算 MA/RSI/MACD） | 盘中实时盯盘选股 |
| 收盘后/历史 | `kline_data`+`capital_flow` | 确定，可重建 | 回测、收盘后选股 |

**数据源能力（已核实，齐备）**
- 批量实时行情：`TencentProvider.GetQuotesAsync(codes)` → `QuoteData`（价/开高低/量额/量比/换手/市值/均价，字段足够拼当日 bar）
- 实时主力资金：`EastmoneyProvider.GetMarketMainFlowAsync`（main 合计；四档实时待确认）
- 动态指标：历史 kline(截至昨日) + 当日实时 bar → `IFeatureCalculator`（与回测同口径）

**架构设计**
- 新增 `RealtimeSnapshotService`：交易时段每 N 分钟 → 批量实时行情 + 历史 kline 拼当日 bar → IFeatureCalculator 算动态指标 + 实时资金 → upsert `daily_market_snapshot` 当日行（反复覆盖）
- 收盘后/回测复用 `SnapshotRebuilder`（kline+capital_flow）
- `StockSelectionService.LoadAsync` 按时段切换数据源（盘中读 snapshot / 收盘走重建），抽象 `ISelectionSnapshotSource`
- Worker 调度：盘中定时 job（9:30–11:30 / 13:00–15:00，每 N 分钟；收盘后停）

**改动点**：`RealtimeSnapshotService`（新）、`MarketSnapshotSyncService`（退役/并入）、Worker 调度、`StockSelectionService.LoadAsync` 数据源切换、配置（刷新间隔/交易时段）

**风险**：实时源限频/性能（全市场约 5000 只分批）；盘中指标是动态近似（结果随价波动）；四档实时资金盘中可能只有 main；收盘后选股切重建依赖 DataSync 当日数据采全。

**工作量**：中等偏大（约 2–4 天）。建议独立分支/会话进行。

## 重要笔记（踩过的坑）
1. **回测数据在漂移**：后台 Worker 持续采集会改变历史 `kline_data`/`capital_flow`，**同参数回测的绝对值会随时间变化**。因子对比必须在**同一次运行内**做，不能跨时间比绝对值。
2. **实盘/回测口径不一致**：实盘读 `daily_market_snapshot`（东财 API），回测用 kline+capital_flow 重建——回测结论到实盘不保证完全同口径。盘中实时改造能收敛这个隐患。
3. **加因子 ≠ 有效**：引擎算法增强（接飞刀/回踩协同/派发惩罚）和 RelativeStrength 都经回测证伪并回滚/不启用。每个新因子必须回测验证，无正向贡献就不进默认权重。
4. **MCP 工具未热加载到本会话工具表**：Claude Code 与 Claude Desktop 的 MCP 注册是两套；本会话通过 `scripts/mcp_call.ps1` 直接 stdio 驱动 `AIStock.Mcp.exe` 调用工具（与 MCP 客户端同代码路径）。
5. **重建 MCP 的锁**：Claude Desktop 长驻 Release 版 MCP 会锁 `bin/Release` DLL；本会话改完用 **Debug** 构建并以 `$env:MCP_EXE` 指向 Debug exe 做回测，避免锁冲突。Desktop 要用新版需重启。

## 工具脚本：scripts/mcp_call.ps1
JSON-RPC stdio 驱动 MCP 工具的批量调用脚本。用法：
```powershell
$env:MCP_MYSQL = "Server=...;Database=aistock;User=...;Password=...;CharSet=utf8mb4;"  # 必填，勿提交明文
$env:MCP_EXE   = "...\AIStock.Mcp\bin\Debug\net9.0\AIStock.Mcp.exe"                      # 可选，默认 Release
$req = '[{"name":"replay_backtest","args":{"strategy":"lowdip","criteriaJson":"","from":"2026-05-05","to":"2026-06-04","holdDays":5}}]'
& scripts\mcp_call.ps1 -RequestsJson $req
```
